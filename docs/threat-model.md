# 위협 모델

현재 보호 대상은 목업 UI입니다. 운영 인증/메일 API는 존재하지 않으며 아래 운영 대책은 **후속 구현 요구 조건**입니다.

| 경계 / 위협 | 현재 조치 | 실제 연결 전 필요한 조치·검증 |
| --- | --- | --- |
| 브라우저에 운영 비밀 노출 | 운영 비밀/API 연동 없음, 테마만 영구 저장; 외부 서비스 이동 링크만 제공 | BFF/서버 세션, 비밀 저장소, 로그 마스킹, 번들 검사 |
| 이메일이 같은 다른 사용자로 연결 | 허구 데이터만 사용 | issuer+sub 불변 매핑, 메일함 unique constraint, 중복/주소/sub 변경 테스트 |
| IDOR: 메시지·첨부·별칭 탈취 | 목업 범위의 폴더 선택 검사(보안 권한 검사가 아님) | 각 API에서 세션 주체+메일함+도메인 검사, 불투명 ID, 타인 ID는 404 |
| 악성 HTML/CSS가 셸 조작 | 텍스트 escape, 권한 없는 sandbox iframe, iframe CSP | MIME 디코딩 후 유지보수되는 sanitizer, URL 스킴 검증, CSS/폼/추적 픽셀 제거, 공격 샘플 테스트 |
| 원격 이미지/링크 추적 | iframe 모든 외부 요청 차단 | 기본 차단 유지, 사용자 명시 허용 및 안전한 프록시 정책 결정 |
| 인증 재전송·세션 탈취·CSRF | 실제 세션·변경 API 없음 | PKCE/state/nonce, 세션 회전, Secure HttpOnly SameSite, Origin+CSRF, 로그아웃/만료 테스트 |
| 관리 권한 상승 | 관리자 예시 토글 및 등록 내용 검토 폼만 존재, 실제 등록 버튼 비활성/API 없음 | 서버 역할 매핑, identity 업무별 권한·대상 범위와 메일 도메인 검사, 기본 거부, 감사 기록; UI와 별도로 테스트 |
| 첨부 오용 | 파일 이름·크기만 표시, 형식/10 MB UI 검사, 업로드/다운로드 없음 | 서버에서도 크기/MIME/권한 검사, 악성 파일 정책, Content-Disposition 및 nosniff |
| 발신자 사칭·중복 발송 | 발송 버튼 비활성 | 본인 주소/허용 별칭 서버 검사, rate limit, 전송 idempotency와 상태 머신 |
| SMTP 수락 후 Sent 저장 실패 | 발송 없음 | accepted/sent-copy-pending 상태 분리. 동일 메일 재전송 없이 Sent 저장만 재시도 |
| 프로비저닝 부분 실패 | 계정/메일함 생성 없음 | Authentik/Mailcow 각 단계 작업 기록, idempotency, 재시도·수동 복구·삭제 별도 승인 |
| 데이터 손실·운영 영향 | 기존 Compose/메일/SOGo/DNS 변경 없음 | 백업 복원 실습, 테스트 도메인, 별도 Compose·origin, SOGo 폴백 |

운영 API가 없는 목업의 프론트엔드 제한을 인증/인가 보안으로 오인하지 않아야 합니다. Cloudflare Tunnel은 TLS/진입 경로이며 애플리케이션 인증을 대체하지 않습니다.

잔여 위험: 화면은 예시 계정을 누구나 볼 수 있는 정적 산출물입니다. 민감 자료를 목업 코드에 추가하지 마세요. 초안은 새로고침하면 사라지는 것을 UI에서 고지하며 실제 업무 메일의 임시보관함으로 사용하지 않습니다.

## CT 분리와 Authentik 관리 확장

- 같은 메일 CT에 배포하더라도 Workspace에 Mailcow 데이터 볼륨/마스터 자격/Docker 소켓을 노출하지 않습니다. Auth CT에는 필요한 API 경로만 서버에서 접근합니다.
- 관리 API를 범용 전달하지 않습니다. 제한된 서비스 계정과 별도로 Workspace 세션 주체·작업별 권한·대상 객체를 검증해 대리 권한 악용을 막습니다. 메일 운영과 identity 관리 권한을 분리합니다.
- 빠른 계정 보안은 본인 재인증 flow로 처리합니다. Authentik의 패스키 RP/origin을 임의 변경하거나 관리자 비밀번호 설정 API를 본인 변경 대신 사용하지 않습니다.
- 초대 이메일/초기 그룹/만료/일회성은 서버가 제한하고, 초대 발급자 비활성 시 미사용 초대를 별도로 폐기합니다. 초대 URL은 로그에 남기지 않습니다.
- 앱 callback은 정확한 HTTPS 주소 및 서버 host 허용 목록으로 제한합니다. Provider/App/정책 부분 생성은 작업 ID와 객체 ID로 추적하고 기본 접근 거부를 유지합니다.
- CalDAV endpoint는 서버에 고정하고 사용자별 principal/collection ACL을 확인합니다. URL 입력을 통한 SSRF와 타인 일정 접근을 차단합니다.
- AMS 로그인 신원과 실제 출입 허가는 분리합니다. 계정 생성/초대/그룹 가입이 물리적 접근을 자동 허용하지 않습니다.
